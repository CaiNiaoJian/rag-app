# 08 · 日志、打包、测试与里程碑

## 1. 日志架构

统一 JSONL 行格式：`{ts, level, src, task_id, doc_id, code, page, msg, detail}`。

| 端 | 方案 |
|---|---|
| 引擎 | loguru（serialize=True）写 `logs\engine-*.jsonl`；10MB 轮转 ×10 份，保留 14 天 |
| Electron | electron-log v5 写 `logs\app-*.log`，同轮转策略 |
| 面向用户的报错 | 带 error_code 双写 `task_events` 表（UI 日志查看器与失败 TOP 的数据源，02 章） |
| 诊断包 | UI「导出诊断包」：logs\ + 系统信息（OS 版本/CPU/内存/磁盘）+ 最近 task_events 打包 zip，供人工反馈；**日志不含文档内容**（只记文件名与元数据），不出机器 |

## 2. 打包与部署

- **electron-builder 26 + NSIS**：`oneClick: true, perMachine: false` → 安装到 `%LOCALAPPDATA%\Programs`，**免管理员**（UAC 不弹窗）；VC++ CRT DLL 随 onedir 附带（不跑需管理员的 vc_redist）。
- **引擎**：PyInstaller **onedir**（启动快、便于逐文件哈希校验）作为 extraResources 打入。
- **Windows 路径边界**：应用 manifest 启用 `longPathAware`；全链路测试中文/空格/特殊字符路径、UNC/网络驱动器（导入时复制进 workspace 规避占用与断连）、文件被 Office 进程占用时提示（复制失败→建议关闭源程序）。
- **体积清单（LZMA 压缩后预估）**：

| 项 | 体积 |
|---|---|
| Electron 运行时 | ~90MB |
| Python 引擎 + 解析库 | ~60MB |
| onnxruntime | ~40MB |
| 深度解析模型（layout + TableFormer fast） | ~250MB |
| OCR 模型（PP-OCRv5 mobile） | ~20MB |
| LibreOffice 裁剪版 | ~300MB |
| Qwen tokenizer + UI 资源 + 字体 | ~30MB |
| **合计** | **~800MB~1.1GB（安装后 1.2~1.5GB），上限 2GB，M1 实测修订** |

## 3. 测试与验收方案

### 3.1 golden corpus（解析质量回归门禁）

50~80 份人工标注期望输出的标准文档集：多栏学术 PDF、扫描 PDF（含倾斜/低分辨率）、图文混排 PPT、复杂表格 Excel（合并单元格/多 sheet/公式）、200+ 页大 PPT、旧版 doc/ppt、损坏文件、密码文件、超大文件（500MB PDF / 10 万行 xlsx）、中英混排。**方法**：CI 脚本批量解析→与标注自动比对打分→输出指标趋势报告；每里程碑作为合入门禁；M1 建 v0（20 份），M2 扩至 50+。

### 3.2 量化验收指标（基准机 8 核/16GB 无 GPU；M1 实测后 M2 冻结）

| 指标 | 门禁值 |
|---|---|
| 解析成功率（有产出或明确分类报错，不崩溃） | ≥ 99% |
| 数字 PDF 文本覆盖率 | ≥ 97% |
| OCR 字符准确率（300dpi 中文扫描件） | ≥ 90% |
| 表格结构还原 TEDS | 常规 ≥ 85%，复杂 ≥ 75% |
| 多栏阅读顺序正确率（块级） | ≥ 90% |
| 100 页文本 PDF 全流程 | ≤ 8 分钟（纯文本快速路径 10 万字 ≤ 60s） |
| OCR 扫描页 | P95 ≤ 10s/页 |
| 损坏/密码文件优雅报错率 | 100% |

### 3.3 桌面端测试

| 项 | 方法 |
|---|---|
| 安装/卸载 | 干净 Win10(1809) 与 Win11 VM 快照；安装后立即导入；卸载后查残留与注册表；覆盖安装后数据迁移正确 |
| **断网验证** | 防火墙阻断全部出站流量跑完整流程 + Wireshark 抓包确认零外联（发布必测） |
| 拖拽 | 多文件/文件夹/非法格式/.kmod/任务进行中拖入 |
| 崩溃恢复 | 任务中 kill 引擎进程：UI 提示、任务标 interrupted、重启后队列一致、soffice 无残留 |
| 长稳 | 连续 200 份文档，内存曲线无泄漏 |
| 路径边界 | 长路径/中文/空格/UNC/文件占用（§2） |

## 4. 里程碑计划（V1，2 名全职开发，约 17 周含 10% 缓冲）

| 里程碑 | 周期 | 可验收交付物 |
|---|---|---|
| **M1 骨架跑通** | 3 周 | 可安装 NSIS 包（**打包链路最大集成风险前置**）；Electron 拉起/守护引擎；HTTP+SSE 通道与任务队列；拖拽导入 docx 与文本 PDF→MD 导出 happy path；日志落盘可查看；CI 出包 + pip-licenses 扫描；corpus v0；性能基线实测（修订 NFR 与体积表） |
| **M2 核心解析** | 5 周 | 七格式全通（LibreOffice 归一化、扫描 PDF OCR、版面分析、表格还原、降级链）；**IR v1.0 冻结**；完整性指标与质量评分；corpus 50+ 接入 CI 回归 |
| **M3 切片与导出** | 3 周 | 结构感知切片（参数可调 + 重切）；六格式导出全通；**数据集 schema 冻结**；仪表盘 v1；文档库三栏对照预览 |
| **M4 模组与模型接口** | 3 周 | .kmod 安装/验签/回滚全流程；**.kmod 格式冻结**；ModelProvider + NullProvider + qa_generate/dataset_build 链路（留空模板 + 规则生成）；错误呈现三级完善 |
| **M5 打磨发布** | 3 周 | 全部量化门禁达标；桌面端测试全通过；性能调优；代码签名 + 杀软送样；用户手册；RC → GA |

**V2 方向性规划**：本地 embedding + 向量库（sqlite-vec 或 LanceDB）→ llama.cpp llm-runtime 模组实装 ModelProvider → 检索问答 UI（引用溯源复用 IR 页码锚点）→ 模型驱动 Q&A 数据集。全部以 .kmod 离线分发，不改 V1 架构。

## 5. 风险清单 TOP 10

| # | 风险 | 缓解 |
|---|---|---|
| 1 | AGPL 传染（PyMuPDF/MinerU 等） | 禁用清单 + CI license 扫描阻断（03 章）；备选购 Artifex 商业授权 |
| 2 | CPU 版面分析/OCR 性能不足 | mobile 级 ONNX 模型、按页并行、可取消、快速路径开关、M1 实测定门禁 |
| 3 | 复杂版面完整性不达标（卖点失守） | 版面模型 + 规则兜底、降级透明、三栏对照预览、corpus 驱动迭代 |
| 4 | 旧版 doc/ppt 转换失真 | LibreOffice 归一化 + 失真样本进 corpus 专项回归 |
| 5 | 安装包体积失控 | 上限 2GB；LibreOffice 裁剪；accurate 模型/高精度 OCR 拆可选 .kmod |
| 6 | Electron + 双进程内存占用 | 按页流式解析、引擎单任务 ≤4GB 超限降级、预览用页快照不驻留原文档 |
| 7 | printToPDF 中文/分页保真 | 内嵌字体 + 专用打印 CSS + 表格跨页表头重复，corpus 含 PDF 导出比对 |
| 8 | .kmod 被篡改/版本错配 | Ed25519 验签 + 逐文件哈希 + 兼容性检查 + 自动回滚（06 章） |
| 9 | PyInstaller 产物杀软误报 | 代码签名证书、提前送样主流杀软、不加壳 |
| 10 | 2 人团队范围蔓延 | 不做清单入需求规格；里程碑门禁验收；V2 需求一律进 backlog |
