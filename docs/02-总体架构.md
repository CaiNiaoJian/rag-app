# 02 · 总体架构

## 1. 进程拓扑

```
┌─────────────────────────────── DocFactory.exe (Electron 42) ───────────────────────────────┐
│  主进程 (main)                                                                              │
│   ├─ 窗口/托盘/生命周期管理                                                                  │
│   ├─ EngineSupervisor：拉起/守护/重启 sidecar，持有 {port, token}                            │
│   ├─ 网络封锁（webRequest 白名单 + CSP，见 §7）                                              │
│   └─ printToPDF 导出服务（离屏 BrowserWindow）                                               │
│  渲染进程 (renderer, sandbox + contextIsolation)                                            │
│   └─ UI（六页信息架构，见 07 章），经 preload 暴露的受控 API 访问引擎与本地文件                 │
└──────────────────────────────────────┬──────────────────────────────────────────────────────┘
                                       │ HTTP + SSE (127.0.0.1:{随机端口}, Bearer token)
┌──────────────────────────────────────▼──────────────────────────────────────────────────────┐
│  engine.exe (Python 3.13, PyInstaller onedir, FastAPI + uvicorn)                            │
│   ├─ 任务调度器（SQLite 持久化队列，并发度 min(CPU/2, 4)）                                    │
│   ├─ 解析流水线：格式归一化 → 解析(L0/L1/L2) → IR → 切片 → 导出（见 03/04/05 章）             │
│   ├─ 模组管理器（.kmod 验签/安装/回滚，见 06 章）                                             │
│   ├─ ModelProvider 注册表（V1 = NullProvider，见 06 章）                                     │
│   └─ 子进程：soffice.exe（LibreOffice headless 转换，单实例队列）                             │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 1.1 生命周期

- **启动**：主进程启动 → 拉起 `engine.exe --port 0 --token <随机128bit>`（token 经命令行传入仅本次有效）→ 引擎绑定 OS 随机端口后向 stdout 打印**单行** `READY {"port":54321}` 握手（stdout 仅此一行，其余日志一律落盘）→ 主进程轮询 `GET /health` 直至 200。超时 15s 判启动失败，报 E06 并给「重试」。
- **守护**：EngineSupervisor 监听子进程退出事件。非零退出 → 自动重启（30s 内最多 2 次，仍失败则 UI 顶栏引擎状态灯变红 + E06 指引）；重启后运行中任务由引擎启动自检标记为 `interrupted`，UI 提示可重试。
- **退出**：窗口关闭 → `POST /shutdown`（引擎完成当前页后落盘退出，宽限 10s）→ 超时 kill 进程树（含 soffice.exe 残留）。

## 2. IPC 协议（Electron ↔ 引擎）

**选型裁决**：本地 HTTP（FastAPI）+ SSE，**不用 stdio JSON-RPC**——onnxruntime/依赖库会向 stdout 打印内容污染帧协议，且 SSE 天然支撑逐页进度流。stdout 仅保留 READY 握手一行。

所有请求带 `Authorization: Bearer <token>`；无 token 或错误 token 一律 401。

### 2.1 端点定义

| 方法与路径 | 用途 | 说明 |
|---|---|---|
| `GET /health` | 存活与版本 | `{status, engine_version, api_version}` |
| `POST /tasks` | 创建任务 | body：`{type: "parse"\|"export"\|"rechunk"\|"module_install"\|"qa_generate"\|"dataset_build", payload: {...}}`；文件一律传**绝对路径**不传内容；返回 `{task_id}` |
| `GET /tasks?status=&page=` | 任务列表 | 分页查 SQLite |
| `GET /tasks/{id}` | 任务详情 | 状态、进度、error_code、阶段时间线 |
| `GET /tasks/{id}/events` | **SSE 进度流** | 事件：`progress`（页粒度 `{page, total, stage}`）、`stage_change`、`degrade`（降级事件）、`done`、`failed` |
| `POST /tasks/{id}/cancel` | 取消 | 设置取消标志，worker 检查点响应；10s 未响应 kill worker 进程 |
| `GET /documents?filter=` / `GET /documents/{id}` | 文档库 | 含完整性指标列 |
| `GET /documents/{id}/ir` / `/chunks` / `/preview/{page}` | IR、切片、页快照 | 大内容返回**文件路径**，renderer 经 preload 读取 |
| `DELETE /documents/{id}` | 删除文档 | 级联删 workspace 目录与各表记录 |
| `GET /stats/dashboard` | 仪表盘聚合 | 见 07 章指标表 |
| `GET /logs?level=&task_id=&q=&page=` | 日志查询 | 查 task_events + JSONL 索引 |
| `GET /modules` / `POST /modules/install` / `POST /modules/rollback` | 模组管理 | 见 06 章 |
| `GET /settings` / `PUT /settings` | 设置读写 | |
| `POST /shutdown` | 优雅退出 | |
| `/v1/models` `/v1/chat/completions` | 本地模型接口（V1 桩） | 见 06 章，OpenAI-compatible |

### 2.2 任务状态机与大结果传输

```
queued → running → done | failed | canceled | interrupted(引擎重启自检标记)
```

- 队列即 SQLite `tasks` 表（引擎重启不丢任务）；调度器按创建序 + 并发度派发。
- **大文件结果一律落盘传路径**：解析产物写 `workspace/{docId}/`，HTTP 响应只含路径与摘要。禁止在 IPC 里传输 MB 级 JSON。

## 3. 磁盘目录布局

根目录 `%LOCALAPPDATA%\DocFactory\`（安装目录只放程序与内置模型，用户数据全在此）：

```
data\app.db                    # SQLite（WAL 模式）
workspace\{docId}\source.*     # 导入时复制的源文件
workspace\{docId}\parsed\doc.ir.json  doc.md
workspace\{docId}\assets\      # 抽取图片
workspace\{docId}\preview\p{n}.png    # 页快照（预览用）
workspace\{docId}\exports\     # 导出产物默认位置（用户可另选目录）
models\                        # 内置模型（layout/tableformer/ocr，随安装包）
modules\{moduleId}\{version}\  # .kmod 安装目录，多版本并存
staging\                       # .kmod 安装中转
backup\                        # 回滚备份与卸载前数据备份
logs\engine-*.jsonl  app-*.log # 引擎/Electron 日志（轮转）
```

**磁盘治理**（对应 E07 事前预防）：
- 导入前预检：`workspace` 所在盘剩余空间 < 源文件总大小 × 3 + 2GB → 阻止导入并报 E07。
- 设置页提供：缓存清理（删 preview/ 与已导出的 exports/）、按文档删除、workspace 迁移到其他盘（复制→校验→切换配置→删旧）。
- 卸载策略：NSIS 卸载器**询问**「是否保留解析数据」（默认保留，提示目录位置）。

## 4. SQLite Schema（六表，冻结契约）

`data\app.db`，WAL 模式，`schema_version` 存于 `meta` 表。

```sql
CREATE TABLE documents (
  id TEXT PRIMARY KEY,              -- uuid
  name TEXT NOT NULL, src_path TEXT NOT NULL, fmt TEXT NOT NULL,   -- doc|docx|pdf|ppt|pptx|xls|xlsx
  size INTEGER, hash TEXT,          -- SHA-256，导入去重提示
  status TEXT NOT NULL,             -- imported|parsing|ok|warning|failed
  page_cnt INTEGER,
  parse_level TEXT,                 -- 整体主级别 L0|L1|L2（混合时取占比最高级）
  text_coverage REAL, table_confidence REAL, ocr_confidence REAL,  -- 完整性指标(0~1)
  degraded_pages INTEGER DEFAULT 0, ir_version TEXT,
  created_at TEXT NOT NULL, parsed_at TEXT
);
CREATE TABLE tasks (
  id TEXT PRIMARY KEY, doc_id TEXT REFERENCES documents(id),
  type TEXT NOT NULL,               -- parse|export|rechunk|module_install|qa_generate|dataset_build
  status TEXT NOT NULL,             -- queued|running|done|failed|canceled|interrupted
  progress REAL DEFAULT 0, stage TEXT,       -- convert|parse|ocr|chunk|export
  error_code TEXT,                  -- E01~E07，见 07 章注册表
  payload_json TEXT, started_at TEXT, ended_at TEXT, created_at TEXT NOT NULL
);
CREATE TABLE chunks (
  id TEXT PRIMARY KEY, doc_id TEXT NOT NULL REFERENCES documents(id),
  seq INTEGER NOT NULL, parent_id TEXT,      -- parent-child：child 行的 parent_id 指向章节块
  kind TEXT NOT NULL,               -- child|parent
  type TEXT NOT NULL,               -- text|table|slide|sheet_region
  text TEXT NOT NULL,
  token_count INTEGER NOT NULL, char_count INTEGER NOT NULL,   -- 双写（内核 token 计，UI 展示字符）
  heading_path TEXT,                -- "第2章>2.3节"
  pages TEXT, node_ids TEXT, meta_json TEXT, hash TEXT
);
CREATE TABLE task_events (          -- 结构化日志/报错（UI 日志查看器与失败 TOP 数据源）
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id TEXT REFERENCES tasks(id), doc_id TEXT,
  level TEXT NOT NULL,              -- info|warning|error
  code TEXT,                        -- E01~E07 或降级事件码 DGR-L1/DGR-L2
  stage TEXT, page INTEGER, message TEXT, detail_json TEXT, ts TEXT NOT NULL
);
CREATE TABLE metrics_daily (        -- 仪表盘趋势预聚合（任务完成时增量更新）
  day TEXT PRIMARY KEY, imported INTEGER DEFAULT 0, parsed_ok INTEGER DEFAULT 0,
  parsed_warn INTEGER DEFAULT 0, parsed_fail INTEGER DEFAULT 0,
  chunk_cnt INTEGER DEFAULT 0, ocr_pages INTEGER DEFAULT 0, total_ms INTEGER DEFAULT 0
);
CREATE TABLE modules (
  id TEXT, name TEXT, type TEXT,    -- parser|ocr|converter|llm-runtime|llm-model
  version TEXT, enabled INTEGER DEFAULT 1,
  prev_version TEXT,                -- 回滚指针
  manifest_json TEXT, installed_at TEXT, PRIMARY KEY (id)
);
```

仪表盘取数策略：**趋势类走 metrics_daily 预聚合，明细类（切片分布/覆盖率/失败 TOP）走 documents/chunks/task_events 实时聚合**（数据量 < 10 万行时实时 GROUP BY 无压力，加常用索引：documents(status)、chunks(doc_id)、task_events(code, level)）。

## 5. 数据与 Schema 迁移策略

离线环境无法远程修数据，迁移必须内建：

1. **SQLite 迁移**：引擎启动时读 `meta.schema_version`，按顺序执行内置迁移脚本（`migrations/000N_*.sql`，只增不改的加列/建表优先）；迁移前自动备份 `app.db` 到 `backup\`；迁移失败恢复备份并报错退出。
2. **IR 兼容**：IR 带 `ir_version`；引擎对旧 minor 版本向后兼容读取；major 升级（破坏性）时旧文档标记 `ir_outdated`，UI 提示「建议重新解析以获得新能力」，**不强制**。
3. **模组升级后的行为**：解析类/OCR 模组升级不自动失效已解析结果；文档库中显示「解析时引擎版本」，用户可自选批量重解析。
4. **应用覆盖安装**：用户数据目录不动；首次启动跑上述迁移链。契约冻结节点：IR 与 .kmod 格式在 M2 结束前允许破坏性变更，之后只允许兼容性演进（见 08 章里程碑）。

## 6. 模组系统与本地模型接口

见 06 章（.kmod 包格式、安装/回滚流程、签名工程、ModelProvider 契约）。架构层面的要点：模组安装目录多版本并存，`modules` 表持版本指针，**重启引擎生效**（V1 不做热替换，换取确定性）；引擎启动自检失败自动把指针回滚到 prev_version。

## 7. 离线与安全强制（代码层面）

「不能联网」= 禁止一切外网流量；本机 127.0.0.1 回环（UI↔引擎↔未来模型服务）允许。

**Electron 侧**：
- renderer：`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`；一切能力经 preload 白名单 API。
- `session.webRequest.onBeforeRequest`：仅放行 `app://`、`file://`、`devtools://`、`http://127.0.0.1:{enginePort}`，其余一律 `cancel`（这是硬闸，CSP 之外的第二道）。
- CSP：`default-src 'self'; connect-src 'self' http://127.0.0.1:*`。
- 禁用 autoUpdater、拼写检查、证书透明上报等 Chromium 联网特性。

**引擎侧**：
- HTTP 服务绑定 `127.0.0.1`（绝不 `0.0.0.0`）+ 每次启动随机 Bearer token → 局域网内其他主机既连不上也无凭据。
- 所有 HTTP client `trust_env=False`（忽略系统代理）；生产构建注入 **socket guard**：`socket.connect` 目标非 loopback 直接抛异常（白名单机制，模型加载仅限本地路径）。
- 无任何遥测/上报代码路径；日志只写本机（见 08 章）。

**验收方法**：防火墙阻断全部出站流量跑完整流程 + Wireshark 抓包确认零外联（见 08 章测试方案）。
