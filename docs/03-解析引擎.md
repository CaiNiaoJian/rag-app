# 03 · 解析引擎

引擎内部五段流水线，每段独立可降级、独立记日志，全程无网络调用：

```
格式归一化层 → 解析层(L0/L1/L2 + OCR) → 中间表示 IR(04章) → 切片层(04章) → 导出层(05章)
```

## 1. 格式路由表

| 格式 | 路径 | 组件（许可） |
|---|---|---|
| PDF 文本型 | 直解 | Docling：docling-parse/pypdfium2 文本层 + RT-DETR 版面模型 + TableFormer（MIT/BSD） |
| PDF 扫描型 | 判定后 OCR | 逐页判定：文本层字符数 < 10/页 → 判扫描页 → RapidOCR 整页识别，坐标回填 IR |
| docx | 直解 | Docling 原生（底层 python-docx，MIT） |
| doc (97-2003) | 转换 | LibreOffice headless → docx → 主管线 |
| pptx | 直解 | Docling 原生（python-pptx，MIT）；每 slide 一节点，演讲者备注并入，图片走 OCR |
| ppt (97-2003) | 转换 | LibreOffice → pptx |
| xlsx | 直解 | openpyxl（MIT），保留 sheet、合并单元格、数据区域 |
| xls | 转换 | LibreOffice → xlsx（xlrd 作离线备选路径） |

**混合页文档**（部分页有文本层、部分页扫描）：逐页独立判定，同一文档内文本页直解、扫描页 OCR。

## 2. PDF 深度解析管线（L0，核心卖点）

1. **文本层抽取**：docling-parse（底层 pypdfium2）取字符与坐标。
2. **版面分析**：RT-DETR layout 模型（CPU 约 3~5s/页）输出块类型（标题/正文/表格/图片/页眉/页脚/脚注/公式）与阅读顺序，处理多栏。
3. **表格结构还原**：TableFormer（默认 fast 档 146MB；accurate 档 213MB 为可选 .kmod）输出 cell 网格（含 rowspan/colspan/表头行标记）。**跨页表合并**：相邻页表格 bbox 水平投影重叠 + 列数一致 → 启发式合并为一个 table 节点，prov 记录多页。
4. **图片抽取**：位图落盘 `assets/`，图内文字走 OCR 并作为 figure 节点的 ocr_text。
5. **页眉/页脚/脚注**：版面模型分类 + 跨页重复检测双保险，各自独立节点类型（导出时可选剔除）。

## 3. 离线 OCR

- **引擎**：RapidOCR（Apache-2.0）+ onnxruntime CPU EP（MIT）。
- **默认模型**：PP-OCRv5 mobile det+cls+rec 中英（合计约 20MB，随安装包）。
- **高精度**：PP-OCRv5 server 档（约 100~200MB）以 .kmod 分发，设置页「高精度 OCR」开关。
- **性能**：整页密集文字单页秒级至十余秒；按页多进程并行（进程数 = min(CPU-1, 4)）；进度按页上报 SSE。
- **用户可控**：处理选项面提供「跳过 OCR（仅提取文本层）」。
- 低置信处理：页均置信 < 0.6 → 文档标 `warning`（E04），预览黄色高亮低置信区域，**不判失败**。

## 4. LibreOffice 归一化层（旧格式）

- 裁剪版 LibreOffice（MPL-2.0，约 300MB；剔除 GPL 组件：部分图标主题、PDF import 扩展），随安装包内置。
- 调用：`soffice --headless --convert-to docx|pptx|xlsx --outdir <staging> <src>`，**独立进程 + 独立 user profile**（`-env:UserInstallation`）。
- 工程约束：LibreOffice 非线程安全 → **单实例转换队列**；120s 超时 kill 进程重试 1 次；仍失败 → 该文档走降级链或报 E03，转换失败样本进 golden corpus 专项回归。
- 合规：进程隔离调用不触发 MPL copyleft 义务；随包附版权声明与源码获取声明。

## 5. 降级链与完整性量化

### 5.1 三级降级（逐页粒度）

```
L0 Docling 精解析 ──失败/超时/低置信──▶ L1 pdfplumber 文本+启发式表格 ──失败──▶ L2 pypdfium2 纯文本 或 整页 OCR
```

- 触发条件：单页解析异常、单页超时（默认 30s）、版面模型置信过低。
- 每次降级写 task_events：`{code: "DGR-L1"|"DGR-L2", page, reason: timeout|exception|low_confidence, detail}`；SSE 推 `degrade` 事件。
- Office 格式（docx/pptx/xlsx）解析简单，仅两级：正常解析 → 纯文本抽取兜底。

### 5.2 完整性指标（每文档产出，入 documents 表 + 仪表盘）

| 指标 | 定义 |
|---|---|
| text_coverage | IR 总字符数 ÷ pypdfium2 原始提取字符数（OCR 页以识别字符计）；> 1 截断为 1 |
| table_confidence | TableFormer cell 置信均值 |
| ocr_confidence | OCR 识别置信均值（无 OCR 页则 NULL） |
| degraded_pages / parse_level | 降级页数；文档主级别 = 占比最高的级别 |

状态判定：全部页 L0 且 coverage ≥ 0.97 → `ok`；有降级页或 E04/E05 → `warning`；无任何产出 → `failed`。

## 6. 许可证审查（闭源商用分发，红线）

**禁用清单**（引入即阻断）：

| 组件 | 原因 |
|---|---|
| PyMuPDF / fitz | AGPL-3.0（商业授权未购买前禁用） |
| MinerU < 3.1 及 doclayout_yolo | AGPL-3.0（MinerU ≥ 3.1 自定义许可含强制署名与自动终止条款，且 AGPL 传递依赖未清理，一并不用） |
| Ultralytics YOLO 系 | AGPL-3.0 |
| camelot（ghostscript 后端） | Ghostscript 为 AGPL |
| PaddlePaddle 运行时 | 许可虽为 Apache，但 Windows CPU 轮子 500MB+ 且 PyInstaller 兼容性差——工程原因禁用（其 OCR 模型经 RapidOCR ONNX 化后使用） |

**流程**：CI 中 `pip-licenses` 扫描，GPL/AGPL 出现即构建失败；新依赖引入需在 PR 中登记本表；发布包内附第三方许可声明文件（`THIRD-PARTY-NOTICES.txt`）。

## 7. Excel 解析细节契约

| 项 | 行为 |
|---|---|
| 公式单元格 | 取**缓存计算值**（openpyxl `data_only=True`）；无缓存值（从未被 Excel 打开保存）时回退公式原文并记 warning |
| 合并单元格 | IR cell 带 rowspan/colspan；取值归左上格 |
| 数据区域 | 每 sheet 按连续非空区域切分为 sheet_region 节点；表头行启发式识别（首行样式/类型突变） |
| 超大表 | 单 sheet > 100,000 行：截断至 10 万行并记 E05 变体 warning（「已截断，建议拆分文件」）；切片层按行组切分复制表头 |
| 内嵌图表/图片 | 图片抽取入 assets 并 OCR；图表对象 V1 仅提取标题与源数据区域引用，不还原图形 |
| 多 sheet | 全部解析；空 sheet 跳过 |

## 8. 性能与资源预估（基准机 8 核/16GB 无 GPU）

| 项 | 估算 |
|---|---|
| 100 页文本型 PDF（含版面+表格） | 3~8 分钟（约 3~5s/页） |
| 100 页扫描 PDF（全 OCR，按页并行后） | 10~25 分钟 |
| 引擎峰值内存 | ≤ 4GB（模型常驻约 1.5GB；按页流式处理，禁止全文档位图驻留） |
| 内置模型体积 | layout ~100MB + TableFormer fast 146MB + OCR ~20MB ≈ 270MB |
