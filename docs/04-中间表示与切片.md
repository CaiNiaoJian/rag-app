# 04 · 中间表示（IR）与切片

## 1. 设计原则

- 所有格式的解析结果归一为**自研 IR**（JSON 文档树）；切片、导出、质量评估、未来 LLM 模组**只面向 IR**，与解析实现解耦。
- 不直接采用 DoclingDocument 作为产品契约（避免被第三方库演进锁死；降级链 L1/L2 与 LibreOffice 路径的产物也要落进同一 schema）。DoclingDocument → IR 做单向映射。
- **冻结契约**：`ir_version` 1.0 在 M2 结束时冻结；此后 minor 版本只增字段（向后兼容读取），major 破坏性变更需评审（见 02 章 §5 迁移策略）。

## 2. IR JSON Schema（v1.0）

存储位置：`workspace/{docId}/parsed/doc.ir.json`。

```json
{
  "ir_version": "1.0",
  "doc": {
    "id": "uuid",
    "source_file": "合同v3.doc",
    "source_format": "doc",
    "convert_chain": ["doc->docx(libreoffice 24.8)"],
    "parse_level": "L0",
    "engine_version": "1.0.0",
    "metrics": {
      "text_coverage": 0.98,
      "table_confidence": 0.91,
      "ocr_confidence": 0.87,
      "disordered_pages": 0,
      "degraded_pages": 0
    }
  },
  "nodes": [
    {
      "id": "n12",
      "type": "section",
      "parent": "n3",
      "children": ["n13", "n14"],
      "level": 2,
      "content": { "text": "2.3 交付条款" },
      "prov": [{ "page": 3, "bbox": [72.0, 340.2, 523.5, 368.9], "charspan": [120, 384] }],
      "confidence": 0.93,
      "extensions": {}
    }
  ]
}
```

### 2.1 节点类型（type 枚举，冻结）

| type | 说明 | content 关键字段 |
|---|---|---|
| section | 标题/章节（树形嵌套还原层级，level=1..6） | text |
| paragraph | 正文段落 | text |
| table | 表格（原子节点，跨页表合并为一个） | table.cells：`[{r, c, rowspan, colspan, text, is_header}]` |
| figure | 图片 | image_ref（assets 相对路径）、caption、ocr_text、ocr=true/false |
| formula | 公式 | text（LaTeX 或原文） |
| slide | PPT 页（子节点为该页内容；备注入 notes 字段） | title、notes |
| sheet | Excel 工作表（子节点为 sheet_region） | name |
| sheet_region | 连续数据区域 | table.cells（同 table）、range（"A1:F120"） |
| header / footer / footnote | 页眉/页脚/脚注（导出时可选剔除或归入脚注区） | text |
| list | 列表（子节点为 list_item paragraph） | ordered |

### 2.2 通用字段

- `prov`：溯源数组，支持一节点多页（跨页表）；`page` 从 1 计，`bbox` 为 PDF 坐标系点位（Office 格式无 bbox 时省略），`charspan` 为原始文本层字符区间（覆盖率计算用）。
- `confidence`：0~1，来自版面/表格/OCR 模型；规则路径（如 docx 直解）恒为 1.0。
- `extensions`：保留域（V2 向量化、LLM 标注等），解析器不写入、下游不依赖。

## 3. 切片策略（在 IR 上执行）

### 3.1 结构感知规则（优先级从高到低）

1. **表格原子**：table / sheet_region 节点不拆断，独立成片（type=table）；超过 token 上限的大表按**行组**切分，每片**复制表头行 + 表标题**。
2. **PPT 按页**：每 slide 一片（含标题+正文+备注）；超限时页内再按结构切。
3. **Excel**：每 sheet_region 一片，超限按行组切分复制表头。
4. **文本聚合**：以**最低级标题**（最深 section）为单位聚合其下段落；超限时段落边界切分，段内句子边界兜底。
5. **孤儿内容**：无标题归属的开头内容归入虚拟根块。

### 3.2 长度与重叠参数（处理选项面可调，默认值即最佳实践）

| 参数 | 默认 | 说明 |
|---|---|---|
| target_tokens | 512 | 目标块长 |
| max_tokens | 1024 | 硬上限 |
| overlap | 12% | 相邻**文本**块重叠（表格/slide 不重叠） |
| split_by_heading | true | 标题边界优先 |
| table_atomic | true | 表格独立成片 |
| drop_header_footer | true | 剔除页眉页脚（footnote 保留归尾） |

- **token 计数**：本地打包 Qwen tokenizer（Apache-2.0，对齐未来 4B/8B 本地模型的中文 token 估计）；chunk 记录**双写 token_count + char_count**，UI 面向非技术用户以字符数展示。

### 3.3 parent-child 两级

- **child**：检索粒度块（上表参数控制），入 `chunks` 表 kind=child。
- **parent**：child 所属章节的全文块（kind=parent，child.parent_id 指向它）。用途：V2 检索时 child 命中→parent 供上下文；Q&A 数据集生成的天然单元。
- chunk 元数据（chunks 表 + 导出 JSON 共用）：`chunk_id / parent_id / doc_id / seq / kind / type / heading_path("第2章>2.3节") / node_ids / pages / token_count / char_count / hash`。

### 3.4 重切（rechunk）语义

- 解析完成即按默认参数生成切片入库（用户无感）。
- 「重切」= 基于已存 IR 重新执行切片层并**整体覆盖**该文档 chunks 记录，**不重新解析**（秒级完成）；导出中心调整切片参数时触发。
