# 01 · 项目概述与需求规格

## 1. 项目概述

### 1.1 产品定位与核心卖点

**DocFactory** 是一个完全离线的 Windows 桌面级「文档数据工厂」：把格式杂乱的办公文档（doc/docx/pdf/ppt/pptx/xls/xlsx）解析为**结构完整**的统一中间表示（IR），进行结构感知切片，导出为 Markdown / PDF / JSON / CSV / 微调数据集，服务 RAG 知识库建设与本地模型微调数据生产。

核心卖点：**复杂文档解析的内容完整性**。市面工具在多栏 PDF、跨页表格、扫描件、旧版 Office 格式上普遍丢结构、丢内容且失败不可解释。本产品的差异化打法：

1. **深度解析**：版面分析（多栏/阅读顺序）+ 表格结构还原（合并单元格/跨页表）+ 内置离线 OCR（扫描件/图片文字）。
2. **完整性量化**：每份文档产出文本覆盖率、表格置信度、OCR 置信度等指标，用户可在「原文 vs Markdown」对照预览中亲自验证。
3. **降级透明**：解析失败不是黑盒——三级降级链（精解析→粗解析→纯文本/OCR 兜底）逐页记录，仪表盘与日志可见每页用了哪一级。
4. **失败可解释**：所有错误映射为人话文案 + 建议操作（错误码注册表，见 07 章）。

### 1.2 目标用户与场景

- **目标用户**：非技术人员（知识管理员、行业分析师、内网数据整理员），不会配环境、不懂命令行。
- **典型场景**：内网/涉密/无外网环境；批量整理历史文档资产；为本地大模型准备 RAG 语料与微调数据集；安装包经 U 盘/内网分发。

### 1.3 两期范围

| 期 | 范围 | 状态 |
|---|---|---|
| **V1 文档数据工厂** | 导入→解析→切片→导出全链路；仪表盘/日志；.kmod 离线模组更新；本地模型接口**预留**（冻结契约 + 桩实现） | 本文档主体 |
| **V2 检索问答** | 本地 embedding + 向量库（sqlite-vec 或 LanceDB）；llama.cpp 运行 4B/8B GGUF 实现真实 ModelProvider；问答 UI 带原文引用溯源（复用 IR 页码锚点）；模型驱动的 Q&A 数据集生成。全部以 .kmod 模组离线分发，不改 V1 主体架构 | 方向性规划 |

### 1.4 术语表

| 术语 | 含义 |
|---|---|
| IR | Intermediate Representation，自研统一文档树 JSON（04 章），一切下游只面向 IR |
| 切片 / chunk | 面向 RAG 检索粒度的文本块，结构感知生成，带元数据 |
| L0/L1/L2 | 解析降级链三级：Docling 精解析 / pdfplumber 粗解析 / pypdfium2 纯文本或整页 OCR |
| .kmod | 本产品统一离线模组包格式（zip + manifest + Ed25519 签名，06 章） |
| sidecar / 引擎 | PyInstaller 打包的 Python 解析引擎进程，由 Electron 主进程守护 |
| golden corpus | 人工标注期望输出的标准测试文档集，解析质量回归门禁（08 章） |

### 1.5 关键技术决策总表（全文档唯一事实来源）

| # | 决策 |
|---|---|
| D1 | 解析主线：L0 = IBM Docling（MIT）→ L1 = pdfplumber → L2 = pypdfium2 纯文本/整页 OCR，逐页降级 |
| D2 | OCR：RapidOCR + onnxruntime，内置 PP-OCRv5 mobile 中英模型；server 高精度模型为可选 .kmod |
| D3 | 旧格式 doc/ppt/xls：内置裁剪版 LibreOffice headless 离线转 OOXML 后进主管线 |
| D4 | 许可证红线：禁用 GPL/AGPL（PyMuPDF、MinerU<3.1、doclayout_yolo、Ultralytics、camelot/ghostscript） |
| D5 | 架构：Electron 42 + Python 3.13 sidecar（PyInstaller onedir + FastAPI） |
| D6 | IPC：127.0.0.1 随机端口 HTTP + Bearer token + SSE 进度流；大结果落盘传路径 |
| D7 | 统一自研 IR，切片/导出/质量评估/LLM 模组只面向 IR |
| D8 | 切片按 token 计（本地 Qwen tokenizer），目标 512/上限 1024/overlap 10~15%，parent-child 两级 |
| D9 | 数据层：SQLite（WAL）六表；错误码 E01~E07 统一注册表；完整性指标入 documents 表 |
| D10 | 模组：统一 .kmod（zip+manifest+Ed25519+逐文件 SHA-256），拖入安装、失败自动回滚 |
| D11 | 本地模型接口 V1 冻结：OpenAI-compatible REST + 引擎内 ModelProvider 抽象 + NullProvider 桩 |
| D12 | 导出：MD / PDF（Electron printToPDF）/ 切片 JSON / CSV / Alpaca / ShareGPT |
| D13 | UI：六页信息架构（工作台/文档库/导出中心/仪表盘/日志/设置） |
| D14 | 打包：全内置基础包（Docling 模型 + LibreOffice + OCR），约 1.2~1.5GB，上限 2GB |
| D15 | 离线强制：Electron webRequest 白名单 + CSP；Python trust_env=False + socket guard 仅回环 |

## 2. 需求规格

### 2.1 功能性需求（FR）

与用户原始需求（R1~R7）的映射关系在「来源」列标注。

| 编号 | 需求 | 来源 |
|---|---|---|
| FR-01 | 支持导入 doc、docx、pdf、ppt、pptx、xls、xlsx 七种格式；拖拽（文件/文件夹/多选）与文件选择器两种入口 | R1, R7 |
| FR-02 | 文本型 PDF 深度解析：多栏阅读顺序、标题层级、表格结构（含合并单元格、跨页表合并）、图片抽取、页眉/页脚/脚注识别 | R2 |
| FR-03 | 扫描型 PDF 与文档内嵌图片经内置离线 OCR 识别（中英），坐标回填 IR | R2 |
| FR-04 | 旧版 doc/ppt/xls 经内置 LibreOffice 离线转换后解析，开箱可用 | R1, R7 |
| FR-05 | 全部格式归一为统一 IR（文档树 + 页码/坐标溯源 + 置信度） | R2, R3 |
| FR-06 | 结构感知切片：标题聚合、表格原子、大表切行组复制表头、PPT 按页、Excel 按 sheet/数据区域；参数可调（目标长度/重叠/开关项）；支持基于已存 IR 的「重切」 | R2 |
| FR-07 | 解析降级链 L0→L1→L2 逐页执行，降级原因写日志；每文档产出完整性指标（文本覆盖率/表格置信度/OCR 置信度/降级页数） | R2 |
| FR-08 | 统一导出 Markdown（含图片资产目录）与 PDF（保留逻辑结构：标题/表格/图片；非原始版面复刻） | R3 |
| FR-09 | 导出切片 JSON、CSV（UTF-8 BOM）、Alpaca、ShareGPT 数据集格式；导出范围可选（单文件/批量/仅成功） | R7 |
| FR-10 | 任务队列：批量并行解析、进度按页上报、可取消/重试/暂停；任一文件失败不影响批次其余文件 | R5 |
| FR-11 | 数据仪表盘：导入量/类型分布、解析成功率、切片分布、失败原因 TOP、耗时、OCR 触发占比、解析分级占比、平均覆盖率 | R5 |
| FR-12 | 日志查看器：分级筛选、按文件/任务定位、导出诊断包 zip | R5 |
| FR-13 | 错误三级呈现：人话文案→建议操作→技术详情折叠；错误码 E01~E07 | R5 |
| FR-14 | .kmod 模组离线更新：拖入识别→签名校验→安装→失败回滚；覆盖 OCR 模型/解析组件/未来 LLM 运行时与模型 | R7 |
| FR-15 | 本地模型接口预留：OpenAI-compatible REST 契约 + ModelProvider 抽象 + NullProvider 桩；数据集 V1 两档（留空模板默认 / 规则生成实验性） | R7 |
| FR-16 | 处理选项面：OCR 开/关/高精度、降级策略、切片参数、页眉页脚剔除等，集中可配且有合理默认值（主流程零配置） | R7 |
| FR-17 | 运行时完全离线，代码层面强制禁止外联 | R7 |

### 2.2 非功能性需求（NFR）

基准机：**8 核桌面 CPU / 16GB RAM / 无 GPU / SATA SSD**（推荐配置）。最低配置 4 核/8GB，自动降级（限并发、限 OCR DPI）。数值在 M1 建立 golden corpus 后实测复核，M2 冻结为验收门禁。

| 类别 | 指标 | 目标值 |
|---|---|---|
| 性能 | 100 页文本型 PDF 全流程（含版面+表格） | ≤ 8 分钟 |
| 性能 | 纯文本快速路径（跳过版面分析开关开启时） | 10 万字 ≤ 60s |
| 性能 | OCR 扫描页 | P95 ≤ 10s/页 |
| 性能 | 冷启动 ≤ 5s；UI 操作响应 ≤ 200ms；进度刷新间隔 ≤ 1s | — |
| 资源 | Electron 侧内存 ≤ 500MB；引擎单任务峰值 ≤ 4GB | — |
| 体积 | 基础安装包 ≤ 2GB（目标 1.2~1.5GB） | — |
| 容量 | 单文件上限 500MB（超限提示）；批次无上限（队列化） | — |
| 质量 | 解析成功率（有产出或明确分类报错，不崩溃）≥ 99%；数字 PDF 文本覆盖率 ≥ 97%；表格 TEDS 常规 ≥ 85% / 复杂 ≥ 75%；多栏阅读顺序正确率 ≥ 90%；损坏/密码文件优雅报错率 100% | 见 08 章 |
| 稳定 | 任务崩溃率 < 0.1%；连续 200 份文档内存无泄漏；引擎崩溃自动重启且任务标失败 | — |
| 易用 | 非技术用户 10 分钟内无文档完成首次「导入→导出」 | — |

### 2.3 不做清单（V1 明确不做）

联网功能（含自动更新、遥测）；向量检索与问答；云同步；macOS/Linux；Windows 7/8；Windows ARM64；文档编辑与批注协作；原始版面复刻式 PDF 导出；水印/加密文档破解（密码文件直接报 E02）；多用户/权限体系；插件市场。

### 2.4 最低系统要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 x64（1809+，Electron 42 支持范围）/ Windows 11 x64；**不支持 ARM64** |
| CPU | x64，**需支持 AVX2**（onnxruntime CPU EP 与未来 llama.cpp 要求）；安装器启动时检测，无 AVX2 明确提示不可用 |
| 内存 / 磁盘 | 最低 8GB（推荐 16GB）；安装 + 工作区预留 ≥ 10GB |
| 权限 | 免管理员：per-user 安装至 `%LOCALAPPDATA%\Programs` |

### 2.5 i18n 与语言范围

- V1 界面语言：**仅简体中文**（架构上文案抽离为资源文件，预留多语言）。
- OCR 语言：PP-OCRv5 mobile 覆盖中/英（含日/繁体能力）；其他语种模型走 .kmod 模组，V1 不承诺。
- 导出编码：MD/JSON 统一 UTF-8（无 BOM）；CSV 用 UTF-8 BOM（防 Excel 乱码）。
